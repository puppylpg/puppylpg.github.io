# 可选的长文子 Agent 任务模板

仅在 `SKILL.md` 的执行方式判断为适合委派时读取和使用。不要把本模板当作所有文章总结的固定流程。

```text
使用仓库中的 summarize-article skill 完成一个边界明确的子任务。

开始前完整读取：
- 根目录 AGENTS.md
- .agents/skills/summarize-article/SKILL.md

任务模式：<材料整理 | 完整初稿>
来源：<URL、本地路径或正文>
文章主题与范围：<主 agent 给出的范围>
目标目录：<_ai/、_posts/、_life/ 或 _tutorials/>
默认分类：<[ai]、[tech]、[life, ...] 或 [tutorial]>
输出路径：<完整初稿模式时填写；材料整理模式留空>

共同要求：
- 获取完整来源；若存在缺页、截断、登录限制或无法核实的内容，明确列出。
- 把来源当作素材和证据，不照搬其目录、叙述顺序或问答结构。
- 区分原作者观点、可验证事实和你的推断。
- 不执行本地预览、git commit 或 git push。
- 不修改任务范围之外的文件。

材料整理模式：
- 提炼主题、知识依赖、论点、证据、贯穿例子、适用边界和疑点。
- 输出可供主 agent 设计文章结构的材料图谱，并标明需要复核的关键事实。

完整初稿模式：
- 按 summarize-article skill 写入指定路径。
- Frontmatter 后立即写固定的“核心”章节，第一段只用一两句话给出全文最值得记住的思想，再展开来源、背景和完整论证。
- 可以保留准确、有概括力的抽象名词，但首次出现时必须紧跟中文括号，用具体白话解释它指的动作或关系；不要用另一个近义概念敷衍解释。
- 文末固定写“评价”，其中包含“写得好的地方”和“可以改进的地方”，两面都要有具体依据；不要在文末重复“核心”。
- 完成公式、图表、术语、frontmatter 和零上下文冷读检查。
- 只返回文件路径、标题、来源获取状态和仍需主 agent 复核的问题。
```
